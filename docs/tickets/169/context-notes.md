## 결정 로그

### 1. 런북 경로 = `docs/pilot/flip-runbook.md` (파운더 확정)

'pilot' 폴더명이 코호트 사건과 어긋나는 건 사실이다. 그런데 **그 폴더는 이미 파일럿 전용이 아니다** — `api-cutover-smoke.md`가 컷오버 문서로 거기 산다. 새 폴더를 파면 런북이 두 곳으로 갈리고 다음 독자가 "왜 얘만 여기 있나"를 판정해야 한다. 상호 링크가 상대경로라 같은 폴더가 무마찰이라는 실무 이유도 같은 방향이었다.

### 2. 게이트 A~G는 **매핑 표만** — 판정 문구 복제 0 (파운더 확정)

AC는 "게이트 A~G 체크리스트가 한 곳에 있다"고 적었고, 문자 그대로 읽으면 체크박스 전문을 리포에 복사하는 것이다. **그러면 #170과 두 벌이 된다.** 이 리포는 같은 사실이 두 곳에 살아 한쪽만 낡는 실패를 이미 두 번 당했다(이전 모듈 "제거 절차" · 프록시 "파일럿 종료 후"). 그래서 **런북은 "어느 절이 실행하나"만 적고 판정 문구는 #170을 정본으로 남겼다.** "한 곳에"의 취지는 흩어지지 말라는 것이지 리포 파일이어야 한다는 것이 아니라고 읽었다.

### 3. 등록 키를 손으로 옮기지 않게 **명령으로 만들었다**

§1이 `gcloud secrets versions access latest --secret=cookmark-register-key`로 값을 직접 읽는다. 자리표시자를 두고 "서버와 같은 값을 넣으세요"라 적을 수도 있었는데 **그러면 오타가 403으로만 드러나고, 403은 화면에서 서버 장애와 구별되지 않는다**(둘 다 `지금 연결에 문제가 있어요.`). 규율을 문장으로 요구하는 대신 **구조로 보장**하는 쪽을 택했다 — `api-cutover-smoke.md` §5의 "토큰은 셸 변수로만, 파일 금지"와 같은 관용구다.

### 4. 롤백 명령은 `infra/README`, 되돌림 **판단**은 런북 — 복제 0

AC가 명령의 자리를 `infra/README`로 못박았다. 그래서 런북 §6은 **언제 어느 되돌림을 쓰는지**(3행 표)만 적고 명령은 포인터다. 이 파일이 이미 모든 `gcloud`를 쥐고 있어 경계가 자연스럽다.

### 5. ★ 롤백 경고를 **셋** 적었다 — AC는 하나만 요구했다

AC가 요구한 것은 스키마 경고 하나인데, 명령을 실제로 써보니 **같은 등급의 함정이 둘 더** 있었다.

- **옛 리비전은 자기 기동 시점의 시크릿 값을 쓴다.** 시크릿 env는 기동 시 1회 해석된다(`infra/README` §3이 이미 적어둔 성질). 등록 키를 회전한 뒤 그 이전 리비전으로 되돌리면 **옛 키로 도는 서버**가 되고, 코호트 APK와 값이 어긋나 등록이 통째로 막힌다. 회전 3종 세트(#167)의 이면이다.
- **롤백은 다음 배포에 자동으로 풀린다.** `api.yml`의 `gcloud run deploy`에 `--no-traffic`이 없어 새 리비전이 100%를 가져간다. `main`에 아무 커밋이나 들어가면 핀이 풀린다 — **롤백은 잠금이 아니라 임시 상태**다. 이걸 모르면 "되돌렸는데 다시 깨졌다"를 서버 장애로 오진한다.

둘 다 워크플로·기존 문서에서 연역되는 사실이고 새 결정이 아니라 적어뒀다.

### 6. ★ CRUD 1바퀴의 **증거를 다시 골랐다**

AC는 "추가 → 재부팅 → 미러 확인"이라 적었는데, 그대로 하면 **아무것도 증명하지 못한다** — 미러는 로컬 영속이라 서버에 안 갔어도 재부팅에서 살아남는다. 로컬 저장과 서버 저장이 구별되지 않는다.

가르는 신호를 찾았다. **하이드레이트 가드**(#165)가 "서버 목록이 비었는데 미러는 안 비었다"에서 발동하고 `errorShown`/`kind:'emptyServerBook'`/`stage:'hydrate'` 이벤트를 **정확히 1건** 남긴다(UI 안내는 의도적으로 없다). 그래서 §3.3은 **재부팅 후 export JSON에 그 이벤트가 없으면 서버 왕복이 실제로 성공한 것**이라고 적었다. 기존 계측을 그대로 쓰는 판정이라 신규 코드가 0이다.

부수로 "에러 카드가 없다"도 확인 항목에 넣었다 — 서버에 닿지 못하면 동기 상태가 `error`로 가 인라인 카드가 뜬다.

### 7. ★ 지연 기록란을 **1행이 아니라 4행**으로 쪼갰다

"콜드/웜을 기록한다"를 한 줄로 두면 `health`를 재고 끝낸다. **그런데 health는 DB를 안 만져 Neon을 깨우지 않는다** — #154가 "진짜 결정 변수는 복합 지연"이라 적은 그 복합이 한 줄엔 안 들어간다. 그래서 겹치는 것이 하나씩 늘어나는 4행으로 만들었다(컨테이너만 → +Neon 웨이크 → +실 LLM 텍스트 → +실 LLM 사진). ②에는 슬라이딩 세션의 왕복 2회(ADR-0012 2026-07-29 정정)가 들어 있다는 것도 함께 적었다.

### 8. ★ 실 Gemini 증거를 **앱 관통 전에** 하나 넣었다

AC의 관통은 에뮬레이터 경로인데, 앱에서 실패하면 "서버가 Gemini에 못 닿는 것"과 "앱 배선이 틀린 것"이 구별되지 않는다. §3.1 끝에 `/api/v1/llm/match` curl 1콜(텍스트, ≈$0.001 미만)을 넣어 **배포된 컨테이너의 설정→팩토리→SDK→파싱 경로**를 앱 없이 먼저 증명하게 했다. 페이로드는 `api-cutover-smoke.md` §4의 것을 그대로 재사용했다(계약이 같다).

### 9. 기대치 고지 문안 — "며칠"은 기대치이지 상한이 아님을 명시

#158 결정 5가 "허용 다운타임 숫자를 박지 않는다"인데 AC의 문안 요구는 "고치는 데 며칠 걸릴 수 있다"이다. 표면상 충돌로 읽힐 수 있어 문안 아래 **"'며칠'은 상한 약속이 아니라 기대치다"** 한 줄을 붙였다. 사이드로드엔 강제 업데이트가 없어 클라이언트 경로엔 완료 시점 자체가 없다는 §6 근거와 연결했다.

문안이 `"지금 연결에 문제가 있어요"`를 **글자 그대로 인용**한다 — 사용자가 화면에서 볼 문구와 카톡 문안이 같아야 신고 유도가 발화한다(#166이 깐 인지 경로).

**앱 안의 「인식이 틀려도 괜찮아요」와 헷갈리지 말라는 주를 달았다.** 둘 다 "기대치 문구"라 불릴 수 있는데 하나는 *오인식*(앱 안·1회성), 하나는 *장애·수리 시간*(기기 밖·배포 전)이다.

### 10. 인접 문서 — 내가 낡게 만든 것 2곳을 함께 고쳤다

- `native-apk-runbook.md` — *"컷오버 빌드 절차는 `api-cutover-smoke.md`가 정본이다"* 가 **절반만 참**이 됐다. 로컬 web은 그쪽, 코호트 릴리스 APK는 이 런북으로 갈랐다.

둘 다 **내 변경이 만든 스테일**이라 같은 PR에서 처리했다(스펙 #161 Further Notes: "삭제가 남은 코드의 안전성을 바꾼다"의 문서판).

## `/code-review` 반영 (Standards · Spec 두 축)

### 하드 결함 1건 — Spec 축이 잡았다. §3.3의 근거가 거짓이었다

초안의 §3.3은 CRUD 증거를 이렇게 적었다 — *"미러만 봐서는 로컬 저장과 서버 저장이 구별되지 않으므로"* export JSON에서 `emptyServerBook`을 찾아 없으면 서버 왕복이 성공한 것이다.

**코드로 확인하니 거짓이다.** `recipe_book_controller.dart`의 `_addToServer`는 미러를 **`server.create()` 응답으로만** 쓰고, 실패 경로는 주석까지 달아 미러를 안 건드린다(*"미저장이므로 미러도 무변화"*). 그러면 **빈 계정으로 시작한 깨끗한 기기에서는 `fetched.isEmpty && recipes.isNotEmpty`가 구조적으로 성립하지 않는다** — 가드가 발화할 수 없고, 그 부재는 아무것도 증명하지 않는다. 하필 §7·함정이 스모크를 깨끗한 기기에서 하라고 지시하므로 **런북이 스스로 무의미하게 만든 확인을 지시하고 있었다.**

수정 — 진짜 증거로 갈아끼웠다. ① 저장 실패는 미러를 안 바꾸므로 **목록에 줄이 생긴 것 자체**가 서버가 받았다는 뜻이다 ② 하이드레이트가 서버 목록으로 미러를 덮으므로 **재부팅 뒤에도 남아 있으면** 서버에서 되받아온 것이다 ③ **에러 카드 없음**이 같은 무게다(못 닿으면 목록은 그대로여도 카드가 뜨고, 그때 화면의 줄은 못 덮인 옛 미러다). 그리고 **가드는 §8 합류에서만 발화한다**는 사실을 §3.3과 함정 양쪽에 명시했다.

### ★ 자체 재독에서 잡은 결함 2건

- **§4가 "`DATABASE_URL`이 틀려도·Gemini 키가 비어도 배포가 green"이라 적었다 — 절반이 거짓이다.** 파이프라인이 마이그레이션을 **배포 전** 러너에서 돌리고 `alembic`도 `get_settings()`를 거치므로, 시크릿이 **비면** 검증에서 죽고 `DATABASE_URL`이 **틀리면** 연결에서 죽는다. 둘 다 CI가 빨개진다. **안 잡히는 것은 정확히 하나 — 값이 있는데 틀린 Gemini 키**다(마이그레이션이 Gemini를 안 부르고 health가 아무것도 안 만진다). 스펙 #161의 원문은 *"health가 200이 나온다"*였는데 내가 *"배포가 green이다"*로 옮기며 범위를 넓혔다. 셋으로 갈라 정확히 다시 적었고, **§3.1의 실 LLM 1콜이 메우는 구멍이 바로 그 하나**임을 연결했다.
- **함정 첫 항목의 403 분기가 처방을 거꾸로 줬다.** *"403이면 키 문제(새 APK가 필요하다)"*라 적었는데, §1이 **Secret Manager에서 읽은 현재 값**으로 curl을 치므로 403은 **컨테이너가 그보다 옛 버전을 읽고 있다**는 뜻이다(회전 후 새 리비전 미배포가 대표적). 새 APK로는 안 고쳐진다. 연결실패/200/403 **3분기**로 다시 썼고, §2 표에서도 함정으로 가라고 연결했다.

### Standards 축 반영

- **정본 중복 — §6이 자기 규칙을 어겼다.** *"명령은 infra §8이 정본… 여기서 복제하지 않는다"*라 써놓고 바로 아래 두 불릿이 롤백 설계 근거와 킬 스위치 기제를 다시 적고 있었다. 둘 다 **주장만 남기고 기제를 삭제**해 포인터로 만들었다.
- **`apps/mobile/README.md`의 중간 포인터가 반쪽 진실로 남아 있었다** — 같은 커밋이 `native-apk-runbook.md`에서 고친 바로 그 형태다. 로컬 web / 코호트 APK로 갈라 적었다.
- **`(ADR-0012 §12 예외)`가 부정확했다** — ADR-0012엔 §12가 없다. 그 절의 이름은 「backend.md §12 데이터 보호에 대한 명시적 예외」라 절 이름으로 바꿨다.
- **`checklist.md`의 `## 표면화` 절이 비어 있었다**(#168 선례는 채운다) — 채웠다.
- **`--format='value(status.traffic)'`가 repr을 뱉는다** — `table(...revisionName, ...percent, ...latestRevision)`으로 바꿨다.

### 반영하지 않은 것

- **"게이트 A~G가 체크리스트가 아니라 라우팅 표다"**(Spec 축이 partial로 표시) — **파운더 확정 결정이다**(위 결정 2). 리포에서 티킹할 목록이 없다는 지적은 사실이나, 두 벌을 만드는 대가가 더 크다는 판단이 먼저 났다.
- **`### ━━━ 되돌릴 수 없는 선 ━━━` 이 prior-art 런북과 다르다**(Standards 축이 style drift로 표시) — **#170 이슈 본문이 같은 장치를 쓴다**(`### ━━━ 코호트에게 APK가 나간다 = 되돌릴 수 없는 선 ━━━`). 상류와 같은 표기를 유지하는 쪽이 옳다.
- **쿼터 공유가 런북 §4와 `infra/README` §9 양쪽에 있다** — 용건이 다르다. §4는 AC가 요구한 **확인 항목**이고, §9는 킬 스위치의 **파급 범위**다. 한쪽을 지우면 그 자리에서 필요한 사실이 사라진다.
- **가드 이벤트 3키가 §3.3과 함정에 둘 다 있다** — 함정은 증상으로 찾아오는 색인이라 검색어가 거기 있어야 한다. 같은 파일 안이라 갈라질 표면이 아니다.

## 표면화 — 고치지 않은 것

- **`d0-readiness.md`의 정본 URL 블록이 여전히 프록시를 가리킨다.** 지금은 참이다(파일럿 2대가 프록시 빌드다). 은퇴 표기는 합류 시점에야 참이라 **#171 몫**이다 — 순서이지 결함이 아니다(ADR-0012 「살아 있는 운영 문서의 갱신은 flip·합류 시점」).
- **루트 `checklist.md`·`context-notes.md`가 #145에 멈춰 있다.** #162·#167·#168이 전부 `docs/tickets/<N>/`에만 썼고 이 티켓도 같다. 루트 두 파일의 처분(갱신할지·지울지)은 이 티켓의 범위가 아니다.
- **`/api/v1/migration/recipes` 경로를 런북에 안 적었다.** 파운더가 직접 칠 일이 없고(앱의 「가져오기」가 부른다) 적으면 손으로 호출할 수 있다고 읽힌다. 계약 정본은 `contracts/openapi.yaml`이다.
- **`min-instances`를 1로 올리는 절차를 안 적었다.** §3.4가 그 결정의 **입력**을 만들 뿐이고, 결정 자체는 실측 후에 난다. 지금 적으면 측정 전에 답이 정해진 것처럼 읽힌다.
