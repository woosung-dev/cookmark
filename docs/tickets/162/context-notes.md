# Context Notes — #162 ADR-0012 + 상류 문서 정합

자율결정 감사 추적. 티켓 [#162](https://github.com/woosung-dev/cookmark/issues/162) · 스펙 [#161](https://github.com/woosung-dev/cookmark/issues/161) · 지도 [#153](https://github.com/woosung-dev/cookmark/issues/153).

## 전제 재확인

이 티켓은 **코드 로직이 0줄**이다. 문서 + 주석·docstring 정합이고, 리스크는 컴파일 에러가 아니라 **다음 세션 에이전트·미래의 파운더를 잘못 안내**하는 것이다. 실제로 이 트랙에서 **"적힌 트리거가 틀렸다"가 두 번 연속 적중**했고(이전 모듈 제거 절차 · 프록시 "파일럿 종료 후" 삭제), 둘 다 문자 그대로 실행하면 사용자 기능이나 파일럿 기기가 깨진다.

**결정은 전부 이미 났다.** 익명 등록은 #156(2026-07-24 CLOSED), 데이터 경계는 #159(2026-07-28 CLOSED), 지도 #153이 같은 날 CLOSED다. **나는 결정을 내리지 않는다 — 이미 난 결정을 리포 문서에 정직하게 기록한다.**

## 결정 로그

### 1. ADR-0012 제목의 `역전` 자리에 `연기`를 넣었다

리포의 역전 ADR 셋(0009·0010·0011)이 전부 `# <새 결정> — <대상> 역전` 꼴이고, 첫 문단이 "부분 역전임에 주의"로 무엇이 살아남는가를 못박는다. ADR-0012는 같은 틀을 쓰되 **`역전`이 아니라 `연기`**다 — 발명이 아니라 관례 위의 한 글자 차이이고, 그 한 글자가 이 ADR에서 가장 오독되기 쉬운 지점이다. 대응 문단도 같은 자리에 **"역전이 아니라 연기임에 주의"**로 뒀다. 근거는 승계가 UPDATE 한 번이고 스키마 변경이 0이라는 사실이며, 이것을 코드로 확인했다(`auth/models.py`의 `uq_accounts_iss_sub`).

### 2. 트리거는 재검토·정리 절 **한 곳에만** 열거한다

승격 4 · 쿼터 3 · 파기 · 임계값 갱신 · 개인정보처리방침이 본문 여러 절의 결론으로도 나올 수 있었다. **전부 "아래 트리거 절"로 가리키게 하고 재열거를 걷어냈다.** 근거 — #145 세션이 코드리뷰에서 정확히 이 실패를 지적받았다(AGENTS.md가 ADR-0011의 목록을 재열거해 정본이 갈림). 리포 규약도 `coding-standards.md` 정본 위계에서 "두 곳에 쓰면 갈라진다"고 못박는다.

### 3. 미러 계약의 정본은 ADR-0012, ADR-0009는 정정 + 포인터만

같은 계약을 두 ADR에 쓰면 갈라진다. ADR-0009 「데이터 경계·보호」의 정정 주는 **"로컬 캐시 없음"이 랜딩된 코드와 다르다는 사실 + 비준 + 정본 포인터**까지만 적고, **안전 근거 ①②(조용한 성공 불가 · 분기 원천 없음)는 복사하지 않았다.** 반대로 프록시 폐기 트리거와 `COOKMARK_SERVER_BASE`는 **ADR-0012에 한 글자도 안 적었다** — 티켓이 "ADR-0012 편입도 하지 않는다(인증 문서라 주제가 흐려진다)"고 명시했다.

### 4. ADR-0009의 이전 코드 "시한부" 줄도 정정했다 — AC 열거 밖, **사용자 승인**

AC는 ADR-0009 정정을 3곳으로 열거하는데, 「데이터 경계·보호」에 네 번째 거짓이 남아 있었다("두 계정 이전 완료 시 제거한다"). 그리고 **삭제 대상 docstring이 바로 그 줄을 상류로 인용**하고 있었다(원 docstring 1행 = "ADR-0009 데이터 이전 절"). docstring만 고치면 상류 ADR은 여전히 "지워도 된다"고 말하고, 티켓이 존재하는 이유("적힌 트리거가 틀렸다")를 자기 문서에서 재현한다. **사용자에게 표면화해 승인받고 정정했다** — #145의 README 선례(AC 밖이지만 goal 정면 위배라 고침)와 동형이다.

### 5. `CONTEXT.md` 꼬리 괄호가 새 서술과 모순돼 함께 고쳤다

주간 백업 항목의 마지막 괄호가 `백업의 보험 성질과 가구 합산 수집 지점 역할은 불변이다`였다(#145가 네이티브 전환 때 쓴 문장). 여기에 "집계 역할은 8/5에 만료"를 얹으면 **같은 항목 안에서 정면 충돌**한다. 괄호를 `백업의 보험 성질은 불변이다`로 좁혔다 — 내 변경이 만든 모순의 정리이지 인접 개선이 아니다. 마크다운 링크도 **평문 참조로 되돌렸다**(`CONTEXT.md`엔 링크가 0건이고 `(ADR-0011·#132)` 꼴이 관례다).

### 6. migration 모듈 — 5개 파일 헤더는 **순수 포인터**로, 조립부만 이유를 짧게 남겼다

원래 5개 파일에 `⚠️ 시한부 모듈. 제거 트리거는 … 참조.`가 반복돼 있었다. 처음엔 같은 자리에 이유("서버 모드 가져오기가 부른다")를 5번 복사했다가 **결정 2와 같은 실패**라 판단해 `# 영구 모듈이다 — 근거와 개명 시점은 src/migration/ __init__.py 참조.`로 줄였다. 이유는 정본 docstring 한 곳에만 산다. 다만 **`main.py` 조립부(import·include 두 곳)에는 짧은 이유를 남겼다** — 거기가 "이 줄 지워도 되나"를 실제로 판단하는 지점이라 포인터만으로는 약하다. (초안에선 include 줄 주석을 지웠다가 **리뷰 반영으로 되살렸다** — 아래 리뷰 반영 절.)

### 7. `router.py`의 "제거 시" 전제도 낡았다

네임스페이스 주석 꼬리가 `별도 네임스페이스라 제거 시 그룹·경로째 사라진다`였다. 제거가 안 일어나므로 **개명 시**로 바꿨다 — 주석의 본체(schemathesis 충돌이라는 CI 실측 근거)는 여전히 참이라 손대지 않았다. 엄밀히 "거짓"은 아니었으나(조건절이다) **"이 모듈은 제거될 예정"으로 읽히는 것**이 이 티켓이 죽이려는 독법이다.

### 8. 작업 문서를 루트가 아니라 `docs/tickets/162/`에 뒀다

루트 `checklist.md`·`context-notes.md`는 tracked이고 현재 **#145 내용**이 들어 있다. #163~#166이 동시에 `ready-for-agent`라 루트를 덮으면 병렬 PR의 충돌 핫스팟이 된다 — 커밋 `44b9657`("docs(#146): 작업 문서를 PR에서 제외 — 병렬 PR #152와 머지 충돌 회피")가 정확히 그 값을 이미 한 번 치렀다. `docs/tickets/{104,141,…}/` 선례를 따랐고 **루트 쌍은 건드리지 않았다**.

### 9. 검증은 "문서가 서로·현실과 안 어긋나는가" + 코드 무손상

`apps/api`는 주석·docstring만 바뀌었으므로 게이트 전량(ruff·format·mypy·pytest 230)을 돌려 무손상을 확인했고, **계약 스냅샷을 재생성해 diff 0**임을 증명했다(라우트·스키마 무변경 = 드리프트 가드 무영향). `flutter analyze`는 Dart 0줄 변경의 스모크다. 진짜 검증은 grep — `파일럿 종료 후`·`로컬 캐시 없음`·`시한부` 잔존이 전부 정정 주석과 짝을 이루는지, ADR-0012에 금지 주장("자연 소멸 = 고아 청소")이 **주장으로** 살아 있지 않은지다.

## 리뷰 반영 (2축 code-review)

**두 축이 같은 하드 결함 1건을 독립으로 적발했다** — ADR-0009 최상단 정정 블록쿼트의 행 번호 `(51행)(13행)(30행)(54행)`가 **삽입 전 값**이라 블록쿼트 2줄 + 중첩 주석 3개만큼 전부 밀려 있었다. 특히 `(13행)`이 정정 후 **`- **코어 = 로그인 + 서버 레시피 북.**`** 을 가리켰는데, 같은 문단이 *"이 ADR의 '코어 = 로그인'은 죽지 않았다"*라고 선언하는 바로 그 줄이다. **포인터를 따라간 독자가 살아 있는 줄을 정정된 줄로 읽는다.** 이 티켓이 존재하는 이유("적힌 것이 거짓")를 자기 산출물에서 축소 재현한 셈이라 즉시 고쳤다 — **행 번호를 버리고 절 이름 + 인용구로 가리킨다**(각 대상엔 이미 눈에 띄는 중첩 정정 주석이 붙어 있고, 이 파일은 합류 때 또 밀린다). 같은 이유로 ADR-0008의 기존 `(29·30·31·35행)` 표기가 이미 어긋나 있는 것도 확인했으나 **HEAD에서 이미 그랬으므로 시점 기록으로 두었다**(내가 만든 결함이 아니다).

- **Duplicated Code — ADR-0008 정정 주가 ADR-0009 정정 주를 거의 그대로 복사했다(Standards, 판단성).** 프록시 폐기 재정의 근거가 두 ADR에 near-verbatim으로 살아 리포 규약("두 곳에 쓰면 갈라진다")에 걸렸다. ADR-0008 쪽을 **결론 한 줄 + 정본 포인터**로 줄였다 — 근거 서술은 ADR-0009 정정 주와 #160에만 산다.
- **`합류`가 두 곳에서 다르게 정의됐다(Standards, 판단성).** ADR-0012는 "파일럿 2대가 서버 빌드로 넘어오고 **프록시를 끊는** 2차 사건", ADR-0008·0009는 "8/5 판정 + 코호트 2주 무사고"였다. 전자는 *무엇*이고 후자는 *언제*라 모순은 아니지만, 용어를 글로서리에 안 넣기로 한 이상 정의가 둘이면 표류한다. ADR-0012에 **정의 + 조건을 한 자리**에 모으고 **프록시 절을 뺐다** — 같은 ADR이 "프록시 은퇴는 이 ADR이 정하지 않는다"고 적고 있어 자기모순이기도 했다.
- **§12 포인터 공백(Standards, 판단성).** Consequences가 "§9 · §12 두 절에 예외가 생긴다"고만 적어, §12 쪽에도 표준 편집이 필요한 것처럼 읽혔다. 실제로는 **§12.4가 "제품별 보관 경계는 각 제품 ADR이 정한다"고 이미 위임**하므로 표준 편집은 §9 한 곳뿐이다. 그렇게 정확히 다시 적었다 — 파운더에게 넘기는 몫이 부풀지 않는다.
- **`main.py` include 줄 주석을 지운 게 아니라 정정했어야 한다(Spec, 사소).** AC 문구가 "조립부의 '시한부' 주석 **정정**"이고, include 줄이 실제로 "이거 지워도 되나"를 판단하는 지점이다. import 줄 주석만 남기면 36줄 떨어져 있다. **짧은 정정 주석을 되살렸다.**
- **`docs/tickets/104/context-notes.md`의 `## 제거 트리거 (시한부)` 절차는 살아 있다(Standards).** 지적은 타당하나 **시점 기록이라 소급 수정하지 않는다**(ADR-0008 선언). 대신 내 checklist의 grep 주장 범위를 정확히(`docs/adr/` + `apps/api/src/`) 좁히고 **표면화 절에 명시**했다 — 조용히 덮지 않는다(AGENTS.md).
