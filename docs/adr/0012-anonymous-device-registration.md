# 익명 기기 등록으로 인증을 연다 — backend.md §9 "소셜 연합만"의 명시적 예외이자 ADR-0009 로그인의 연기

2026-07-24 사용자(파운더) 그릴링 결정으로 `apps/api`의 인증을 **익명 기기 등록**으로 연다(인증 화해 [#156](https://github.com/woosung-dev/cookmark/issues/156) · 데이터 경계 [#159](https://github.com/woosung-dev/cookmark/issues/159)(2026-07-28) · 지도 [#153](https://github.com/woosung-dev/cookmark/issues/153) · 실행 스펙 [#161](https://github.com/woosung-dev/cookmark/issues/161)). 앱 최초 실행 시 서버가 익명 계정 `(iss="device", sub=<서버 발급 uuid>)`와 세션을 자동 발급한다 — 로그인 화면 0, 사용자 탭 0. 이 결정은 `.claude/rules/backend.md` §9 「소셜 연합만」에 **명시적 예외**를 신설하고, [ADR-0009](0009-apps-api-materialization.md)가 "코어 = 로그인 + 서버 레시피 북"이라 적은 그 로그인을 **역전이 아니라 연기**한다. ADR-0009가 인증 역전을, [ADR-0010](0010-url-content-extraction.md)이 추출 역전을, [ADR-0011](0011-native-android-pilot-target.md)이 배포 타깃 역전을 정직하게 기록한 것과 같은 취지로, 이 예외와 그것이 남긴 새 제약을 여기 남긴다.

**역전이 아니라 연기임에 주의** — **ADR-0009의 "코어 = 로그인"은 죽지 않았다. 미뤄졌을 뿐이고, 미뤄진 자리에 승계 경로가 이미 깔려 있다.** 익명 계정 행의 `iss`/`sub`를 실제 신원으로 UPDATE하면 그것이 로그인 승격이다 — **스키마 변경 0**이고 `uq_accounts_iss_sub`(`apps/api/src/auth/models.py`)가 그대로 성립한다. §9의 세션 저장·운반·즉시 폐기도 **전부 표준 그대로**다. 벗어나는 것은 **신원 획득 한 곳**뿐이다 — 부분집합이지 우회가 아니다.

**발효는 flip 시점이다** — **flip = 새 코호트 APK가 처음부터 `apps/api`를 싣는 사건**이고(정의는 스펙 #161 A절), **코호트 = 앱을 받는 지인 5~20명**이다. 결정은 지금 확정되고 문서는 지금 커밋되지만 **파일럿 2대의 APK는 flip에서 무접촉**이라 [ADR-0004](0004-single-blind-pilot.md) 단일맹검 측정 순도가 자동 충족된다. 8/5 파일럿 판정은 flip의 조건이 아니라 **합류 = 파일럿 2대가 서버 빌드로 넘어오는 2차 사건**의 조건이다 — 정확히는 **8/5 판정 + 코호트 2주 무사고**다. 합류가 그 밖에 무엇을 함께 하는지(엔트리 통합·프록시 은퇴)는 이 ADR이 정하지 않는다. 되돌릴 수 없는 선은 정확히 한 곳 — 코호트에게 APK가 나가는 순간이고, 그 앞은 서비스 삭제·재배포로 공짜로 뒤집힌다.

## 결정 계보 — 셋이 아니라 넷째 선택지 (2026-07-24 그릴링)

- **질문은 셋이었다** — #156이 물은 것은 무인증 라우트 · 사전프로비저닝 토큰 유지 · 진짜 로그인(ADR-0005 역전) 셋 중 하나였다. **파운더는 넷째를 만들었다** — 익명 기기 등록.
- **셋을 가른 축 = "지인 5~20명 코호트 배포"** — 첫 실사용자를 그 규모로 고정하자 사전프로비저닝은 **1빌드=1계정**으로 무너지고, 진짜 로그인은 [#155](https://github.com/woosung-dev/cookmark/issues/155) 실측(앱 측 4~7일)이 붙으며, 무인증은 공개 URL의 LLM 비용 표면을 연다. 익명 등록만 **1빌드=N계정**이면서 추가 비용이 ~1일이다.
- **근거 한 줄이 나중에 정정됐다** — #156 결의문은 *"30일+ 비활성 계정은 자연 소멸 → 고아 청소"*라 적었고, #159가 코드로 확인해 **거짓임을 정정**했다(reaper 0건). **결정은 안 흔들렸고 근거만 바뀌었다** — ADR-0009의 Lax 조항이 "결론은 살아남았고 근거만 바뀌었다"고 적은 것과 같은 형태다. 정확한 서술은 아래 슬라이딩 세션 절이 정본이다.

## backend.md §9 「소셜 연합만」에 대한 명시적 예외 — 부분집합이지 우회가 아니다

- **예외는 한 줄뿐이다** — §9 첫 불릿의 *"소셜 연합만 — IdP의 OIDC 코드 플로우로 로그인한다"*. 익명 등록은 **IdP를 거치지 않고 서버가 신원을 발급**한다. 그게 벗어나는 전부다.
- **따르는 것을 열거한다(변경 0)** — 세션 저장 = 앱 소유 관계형 DB의 세션 테이블 · 운반 = 네이티브 보안 저장소 + `Authorization: Bearer` · 로그아웃 = 세션 행 삭제 · `userId`를 클라이언트에서 인자로 받지 않고 검증된 세션에서 추출(`apps/api/src/auth/dependencies.py`) · stateless JWT 미채택. IdP를 붙이는 순간 §9 전체가 무수정으로 다시 적용된다.
- **§12.1 최소 식별자는 오히려 더 엄격해진다** — provider의 `sub`조차 받지 않는다. 서버가 만든 난수 uuid가 계정 식별자의 전부다. 이메일·닉네임·프로필 무수집은 무변경이고, 이메일 자동 병합 금지는 **병합할 이메일 자체가 없어** 자명하게 성립한다.
- **예외를 표준 본문에 어떻게 남기나** — `backend.md` §9에 "익명 등록 예외 — ADR-0012 참조" **포인터 한 줄**을 단다. 그 파일은 gitignored 로컬 정본이라 이 ADR을 낳은 PR에 포함되지 않는다(파운더 몫). **근거를 표준에 복사하지 않는다** — 정본은 이 ADR이다.

## 익명 계정의 신원 모양과 승격 경로 — 역전이 아니라 연기다

- **`POST /auth/device`** — 익명 계정 `(iss="device", sub=<서버 발급 uuid>)`와 세션을 **함께** 발급한다. 응답은 **기존 로그인 콜백과 같은 세션 스키마**(토큰 · 만료 · 계정)를 재사용한다 — 새 계약 표면을 만들지 않는다.
- **로그인 화면 0, 사용자 탭 0** — 등록은 부팅 경로에서 일어나고 사용자에게 보이지 않는다. 사용자는 계정이 생겼다는 사실조차 의식하지 않는다.
- **브라우저 왕복이 없다** — 그래서 #155가 조사한 커스텀 스킴 리다이렉트 접합과 매니페스트 `taskAffinity=""` 복귀 문제가 **여기선 발생하지 않는다**. 그 배선은 승격 시점에야 필요하다.
- **승격 = UPDATE 한 번** — 익명 계정 행의 `iss`/`sub`를 실제 신원으로 UPDATE하면 그 행이 그대로 로그인 계정이 된다. **스키마 변경 0**, `(iss, sub)` 유니크 제약 그대로, 레시피 북은 `owner_id`가 안 바뀌므로 **따라온다**.
- **대조 — 사전프로비저닝 토큰은 승계가 구조적으로 불가능하다.** `apps/api/scripts/seed_sessions.py`가 `iss="local-seed"`를 쓴다. 나중에 같은 사람이 로그인하면 `(iss, sub)`가 달라 **계정이 갈린다** — 지금의 편의가 미래의 승격을 태우는 형태다. 이것이 넷째 선택지를 고른 이유의 절반이고, 나머지 절반은 규모(1빌드=1계정)다.
- **승격이 언제 발화하는지는 여기 적지 않는다** — 정본은 맨 아래 재검토·정리 트리거 절이다.

## 등록 시크릿 COOKMARK_REGISTER_KEY — 위협 모델을 명시한다

- **무엇이 열리고 무엇으로 닫나** — `apps/api`의 LLM 라우트 셋은 전부 `CurrentAccount`를 요구해(무세션 401) 공개 URL의 LLM 비용 표면을 닫고 있었다. 익명 등록은 그 장치를 무효화한다(아무나 무한 등록 → Gemini 키 소모). `POST /auth/device`가 **빌드에 박힌 `COOKMARK_REGISTER_KEY`를 요구**해 다시 닫는다.
- **위협 모델을 명시한다 — "URL을 찍어보는 스캐너"이지 "APK를 리버싱하는 공격자"가 아니다.** 근거는 5~20명 사이드로드 · APK 비공개다. **키가 APK에 평문으로 산다는 사실을 숨기지 않는다** — 이 위협 모델 아래 그것이 감수인지 결함인지가 갈리고, 모델이 바뀌면(공개 배포) 결함이 된다.
- **레이트 리밋을 지금 만들지 않는다** — Redis 신규 도입은 원가 리서치 [#154](https://github.com/woosung-dev/cookmark/issues/154)가 세운 **"월 $0" 전제를 파괴**한다. 계정당 LLM 쿼터도 지금 만들지 않는다.
- **키 회전은 등록에만 영향한다** — 기존 세션은 불변이고, 새 키로 APK를 다시 뿌리면 끝난다. **회전이 사용자 데이터를 건드리지 않는다는 것**이 이 설계의 값이다.

## 슬라이딩 세션 — 30일 값 유지 + 갱신 추가

- **바뀌는 것은 갱신 하나** — `SESSION_TTL = timedelta(days=30)`(`apps/api/src/auth/service.py`)의 **숫자는 유지**하고, **세션 검증이 성공하면 `expires_at`을 연장**한다. 활성 사용자는 실질 무만료가 된다.
- **왜 필요한가** — 익명 등록에서는 **토큰이 계정으로 가는 유일한 링크**다. 갱신이 없으면 30일 뒤 조용한 401 → 재등록 → 새 계정 → **레시피 북 고아**가 된다. 사전프로비저닝 시절엔 "알려진 절벽"이었지만 실사용자가 붙는 순간 아니다.
- **정확히 적을 것 — 30일+ 비활성에서 소멸하는 것은 도달 가능성이지 데이터가 아니다.** 세션 검증(`apps/api/src/auth/repository.py`)은 `expires_at > now`로 **거르기만** 한다. **만료된 세션 행도, 비활성 계정 행도, 그 계정의 레시피도 지우는 코드가 없다 — reaper 0건.** 30일이 지나면 그 계정의 레시피는 **누구도 못 읽지만 영원히 남는다.**
- **그래서 이 ADR은 "자연 소멸 = 고아 청소"라고 적지 않는다** — 그 문장은 거짓이고, #156 결의문이 한때 그렇게 적었다가 #159가 코드로 정정했다. §12.3 「지체 없는 파기」와 정합하지 않는다는 것까지 그대로 적는다. 잔존의 처분은 아래 §12 예외 절이 정본이다.
- **알려진 대가 — 갱신은 인증된 요청마다 UPDATE 1회다.** DB가 Neon 싱가포르(ap-southeast-1)라 왕복 ~60-70ms가 요청당 한 번 더 붙는다(ADR-0009 스택·배포 절).
- **임계값 기반 갱신(남은 수명이 절반 이하일 때만 UPDATE)은 최적화이지 결정이 아니다** — 측정된 적 없는 숫자에 선지불하지 않는다. 발화 조건은 아래 트리거 절.

## IdP 4필드 Optional 강등 — 부재는 OIDC 라우트가 쓰일 때만 시끄럽다

- **현 상태가 flip을 막는다** — `apps/api/src/core/config.py`의 카카오·구글 client id/secret 4필드가 **기본값 없는 필수**라 값이 없으면 **앱이 아예 뜨지 않는다**. 마이그레이션 실행 단계도 같은 설정 검증을 거치므로 같이 막힌다.
- **그 설계는 옳았고 전제가 바뀌었다** — *"없으면 부팅이 실패하는 편이 조용한 로그인 장애보다 낫다"*는 판단은 **로그인이 코어**라는 전제 아래 옳았다(코드 주석 그대로). **익명 등록이 그 전제를 연기했다.**
- **강등의 정확한 의미 — 부재는 인증(OIDC) 라우트가 실제로 쓰일 때만 시끄럽게 실패한다.** 부팅은 통과하고, OIDC 로그인·콜백 라우트가 호출되는 순간 명확한 실패를 낸다. **조용한 폴백을 만들지 않는다** — 원 판단이 막으려던 "조용한 로그인 장애"는 그대로 막힌다.
- **실효** — IdP 콘솔 등록([#100](https://github.com/woosung-dev/cookmark/issues/100))이 **flip 차단자에서 진짜로 빠진다**.

## 데이터 경계 — 미러 계약 · 하이드레이트 가드 · 401 재등록

셋을 한 절에 묶는다. 인과가 하나이기 때문이다 — 미러를 비준하고, 가드가 그 미러를 지키고, 그래서 401 재등록이 안전해진다.

- **경계 1장** — 서버 = 계정 + 레시피 북 / 로컬 = 이벤트 로그 정본 + 등록 토큰 + **렌더 미러** / 기기 밖 = export JSON. 사진은 양쪽 모두 무저장이다.
- **미러 계약 — 레시피 북의 로컬 사본은 캐시가 아니라 비준된 렌더 미러다.** ADR-0009의 "서버 정본 + 로컬 캐시 없음"은 랜딩된 코드(컷오버 [#121](https://github.com/woosung-dev/cookmark/issues/121))와 다르므로 **명시적으로 정정한다**. 걷어내면 동기 read 소비자 셋이 전부 async로 뒤집히고, 걷어낸 자리에 내구성이 생기지도 않는다.
  - **안전 근거 ① 조용한 성공이 구조적으로 불가능하다** — 매칭 자체가 서버 호출이라 **스테일 미러로 매칭이 성공할 길이 없다.** 미러가 살리는 것은 "목록이 보인다"뿐이다.
  - **안전 근거 ② 분기의 원천이 없다** — 익명 등록은 **1계정 = 1기기**다. 다른 기기가 같은 계정의 서버 북을 고칠 수 없다.
- **하이드레이트 가드 — 빈 서버 목록은 비어 있지 않은 미러를 덮지 않는다.** 1계정 1기기 전제 아래 그 조합은 **"아직 이전 안 됨"만 의미할 수 있어 위양성이 구조적으로 0**인 불변식이다. **가드의 범위는 미러 보존 + 이벤트 1건까지**이고 **UI 안내는 만들지 않는다**(안내는 런북이 한다).
- **401은 재등록이다 — 새 계정 + 로컬 미러 보존.** 가드가 미러를 지키고 매칭이 제목·재료를 요청 본문으로 받으므로 **코어 루프가 그대로 산다.** 사용자가 잃는 것은 이미 값이 0이던 서버 사본뿐이다(아래 Consequences의 정직한 부정 참조). **"세션 만료" 문구를 사용자에게 노출하지 않는다** — 로그인이 없는 사용자에게 설명할 수 있는 개념이 아니다.

## backend.md §12 「데이터 보호」에 대한 명시적 예외 — 고아 잔존과 파기

- **이미 만족돼 있는 것부터 적는다** — 탈퇴 엔드포인트가 즉시 하드 삭제 + FK CASCADE로 배선돼 있고(`apps/api/src/auth/router.py`), §12.2 스코프드 레포지토리 격리와 교차 테넌트 404가 실 DB로 검증돼 있다([#103](https://github.com/woosung-dev/cookmark/issues/103)). **flip이 이걸 바꾸지 않는다.**
- **탈퇴 UI를 노출하지 않는다** — 로그인이 없는 사용자에게 "탈퇴"는 의미가 성립하지 않고, 사용자가 실제로 하는 행위는 **앱 삭제**다. **엔드포인트는 지우지 않는다** — 승격 시 UI를 얻는다.
- **명시적 예외 — 앱 삭제로는 서버 데이터가 지워지지 않는다. 도달 불가 계정은 잔존하며 파기는 파운더가 일괄 삭제로 수행한다.**
- **자동 reaper를 만들지 않는 이유 셋** — ① 되돌릴 수 없는 파괴다 ② "도달 불가" 판정을 서버 시각 하나에 맡긴다 ③ 신규 서버 코드가 flip 임계경로를 늘린다. 규모는 5~20명 × 재설치 몇 회 = **수십 행이라 실해가 0**이다.
- **§12.4가 이 예외를 허용한다** — *"제품별 보관 경계는 표준이 아니라 각 제품의 ADR이 정한다."* 다만 §12 원칙("쓸 곳이 정해지지 않은 것은 남기지도 않는다")과 어긋나는 상태임을 숨기지 않는다 — 그래서 **화해가 아니라 예외**다. 파기가 언제 발화하는지는 아래 트리거 절.

## Considered Options

- **사전프로비저닝 토큰 유지**(컷오버 #121의 현행 우회) — 추가 비용 0. 기각 — **1빌드=1계정이라 5~20명 코호트에서 구조적으로 무너지고**, `iss="local-seed"`라 로그인 시 계정이 갈려 **승계가 불가능**하다.
- **진짜 로그인 지금 도입**(ADR-0009 원안 집행) — 다기기·복구가 즉시 열린다. **기각이 아니라 연기** — #155 실측이 앱 측 4~7일이고, 재설치 복구는 `android:allowBackup="false"`([#131](https://github.com/woosung-dev/cookmark/issues/131) · [#136](https://github.com/woosung-dev/cookmark/issues/136))로 **이미 없는 요구**다. 없는 요구에 그 시간을 선지불하지 않는다(`mobile.md` §8 사전 확장 금지).
- **무인증 라우트**(LLM 라우트만 세션 면제) — 가장 싸다. 기각 — 공개 URL의 LLM 비용 표면이 열리고, 서버 레시피 북의 **소유자가 성립하지 않는다**(§12.2 스코프드 레포지토리가 `owner_id`를 요구). §9·§12를 동시에 깬다.
- **레이트 리밋·계정당 쿼터 지금 도입** — 기각. Redis 신규가 "월 $0" 전제를 깬다(#154). 트리거로 미룬다.
- **자동 계정 reaper** — 기각. 위 §12 예외 절 참조.
- **미러를 걷어내 ADR-0009를 문자 그대로 집행** — 기각. 동기 read 소비자 셋이 전부 async로 뒤집히고 export 원본이 사라지는데, 그 대가로 얻는 내구성이 0이다. **미러를 비준하고 ADR을 정정하는 쪽**을 택했다.
- **가드 없이 런북 규율만** — 기각. 평생 2회짜리 사건이라 과설계라는 주장은 맞으나, **조용한 데이터 파괴는 실패 등급이 다르고** 가드의 불변식엔 위양성이 없다.

## Consequences

- **`backend.md` 두 절에 예외가 생기지만 표준 편집은 §9 한 곳뿐이다** — §9(신원 획득)는 "소셜 연합만"을 정면으로 벗어나므로 **포인터 한 줄이 필요**하고, §12(고아 잔존)는 **§12.4가 이미 "제품별 보관 경계는 각 제품의 ADR이 정한다"고 위임**하므로 **표준을 고칠 필요가 없다** — 예외의 정본은 위 §12 예외 절이다. 표준은 회사 자산이라 **gitignored 로컬 정본이고 이 ADR을 낳은 PR에 포함되지 않는다** — §9 포인터는 파운더가 리포 밖에서 반영한다(ADR-0009의 "`backend.md`가 4곳 바뀐다" 선례와 동형).
- **ADR-0009가 정정되지만 이 ADR이 그 전부의 정본은 아니다** — **미러 계약만 여기가 정본**이고 ADR-0009는 짧은 정정 + 포인터를 받는다. 프록시 폐기 트리거("합류 후")와 `COOKMARK_SERVER_BASE` 분리는 **ADR-0009·ADR-0008의 인라인 정정**이지 이 ADR의 내용이 아니다 — 프록시 은퇴는 새 결정이 아니라 **이미 있는 결정의 발화 조건 교정**이라, 새 ADR을 내거나 여기 편입하면 같은 결정이 두 곳에 살아 다음 독자가 정본을 판정해야 한다.
- **파일럿 2대는 무접촉이다** — ADR-0004 단일맹검이 유지되고 앱의 기본 진입점은 flip에서 바뀌지 않는다.
- **IdP 콘솔 등록(#100)이 flip 차단자에서 빠진다** — Optional 강등의 실효다.
- **정직한 부정 — v1에서 서버 정본화는 사용자에게 내구성을 주지 않는다.** 계정 식별자가 기기 보안 저장소의 등록 토큰이고 클라우드 백업이 꺼져 있어, **토큰이 죽으면**(기기 유실 · 데이터 삭제 · 다른 키로 재설치) 새 계정을 받아 옛 서버 레시피가 도달 불가이고, **토큰이 살면**(같은 키스토어 · `versionCode`+1) 로컬 미러도 같이 산다. 두 경우 모두 서버 사본이 사용자에게 주는 값이 0이다. **flip의 동기는 내구성이 아니라 구조** — 로그인 승격·다기기·진짜 복구가 앉을 자리를 만드는 것이다. 그 귀결로 **export/import 한 쌍이 유일한 진짜 보험**이 된다. 값을 부풀려 적지 않는다.
- **남기는 부채를 열거한다** — 고아 계정 누적(수십 행 규모) · 등록 키가 APK에 평문 · 계정당 LLM 쿼터 없음 · 코호트 이벤트 미수집(서버에 받을 곳이 0건인 **결정**이지 결함이 아니다). 넷 다 트리거로만 정당화되는 상태이고 만료를 지켜야 한다.
- **살아 있는 운영 문서의 갱신은 flip·합류 시점이다** — 정본 URL 은퇴 표기 등은 그때에야 참이 되므로 지금 미갱신인 것은 **결함이 아니라 순서**다(ADR-0011의 "의도된 잔존" 조항과 같은 장치).
- **이 ADR은 스펙 #161 구현 티켓들을 blocking하지 않는다** — 계약은 스펙이 이미 담고 있고, 이 문서는 그 계약의 상류 기록이다.

## 재검토·정리 트리거

**이 ADR의 모든 트리거가 여기 한 곳에 모인다** — 위 절들은 여기를 가리킬 뿐 재열거하지 않는다.

- **승격 — 진짜 로그인 (넷 중 하나)** ① 한 사람이 둘째 기기를 요구 ② 재설치로 레시피 북을 잃고 아파함 ③ 코호트 > 20명 ④ 공개 배포.
  - **발화 시 동반 작업** — IdP 4필드 재필수화 · 탈퇴 UI 노출 · `iss`/`sub` UPDATE 승계 · 고아 일괄 파기 1회 · **1계정 1기기 전제 재검토**(미러 계약의 안전 근거 ②가 여기에 걸려 있다).
- **계정당 LLM 일일 쿼터 (셋 중 하나)** — 코호트 > 20명 · 월 LLM 원가 > $5 · 등록 키 유출 확인. 레이트 리밋 재검토는 셋째와 발화 시점을 공유한다.
- **고아 파기 — 승격 시 또는 코호트 종료 시.** 파운더 일괄 삭제다. **자동 reaper는 이 트리거로도 생기지 않는다** — 수동이 결정이다.
- **임계값 기반 세션 갱신** — flip 관통 스모크의 콜드·웜 지연 실측 후 필요가 드러나면.
- **개인정보처리방침** — ADR-0009가 남긴 트리거는 **살아 있다.** 익명 등록은 provider `sub`조차 안 받아 수집이 더 줄지만 **서버 발급 uuid도 식별자**다. 발화 시점은 위 승격 트리거 ④(공개 배포)와 공유한다.
- **이 ADR의 발효 자체 = flip.** 그 전에 결정을 되돌리는 비용은 0이다.
- **범위 밖 명시** — 프록시 은퇴 시퀀싱 · 되돌림 2단(리비전 롤백/roll-forward) · 실패 문구 구분은 이 ADR이 정하지 않는다. 각각 ADR-0009·ADR-0008 인라인 정정과 스펙 #161의 몫이다.
