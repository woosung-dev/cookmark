# apps/api flip 런북 (#169)

**flip = 새 코호트 APK가 처음부터 `apps/api`를 싣는 사건**이다(스펙 [#161](https://github.com/woosung-dev/cookmark/issues/161) A절 · [ADR-0012](../adr/0012-anonymous-device-registration.md)). 설치된 파일럿 2대의 이관이 **아니다** — 그 2대는 flip에서 무접촉이고, 8/5 판정은 flip의 조건이 아니라 **합류**(2차 사건)의 조건이다. 이 문서는 코호트 APK를 **만들고 · 배포된 서버로 관통시키고 · 뿌리고 · 실패하면 되돌리고 · 합류에서 파일럿 2대를 옮기는** 기계적 절차의 정본이다.

에이전트가 이 절차를 쓰고 **파운더가 실행한다**([#141](https://github.com/woosung-dev/cookmark/issues/141)과 같은 역할 분담). 실행 티켓은 [#170](https://github.com/woosung-dev/cookmark/issues/170)이다.

여기 **없는 것** — GCP 프로비저닝·`gcloud` 명령·리비전 롤백 명령·킬 스위치([`infra/README.md`](../../infra/README.md)) · 키스토어 1회 생성·APK 산출물 검증·설치 손가락 순서([`native-apk-runbook.md`](./native-apk-runbook.md) §1·§2·§4·§5) · 로컬 스모크([`api-cutover-smoke.md`](./api-cutover-smoke.md)) · 파일럿 계측·판정 지표([`d0-readiness.md`](./d0-readiness.md)) · 결정 근거([ADR-0012](../adr/0012-anonymous-device-registration.md) · 스펙 #161). 두 곳에 쓰면 갈라진다.

## 1. 좌표 — 이 셸에서 계속 쓰는 값들

```bash
export REGION="asia-northeast3"                # 서울 — .github/workflows/api.yml의 env와 같은 값
export SERVICE="cookmark-api"
export URL="$(gcloud run services describe "$SERVICE" --region="$REGION" --format='value(status.url)')"
export REGISTER_KEY="$(gcloud secrets versions access latest --secret=cookmark-register-key)"
echo "$URL"
```

APK 경로·`adb`·`apksigner`는 [`native-apk-runbook.md`](./native-apk-runbook.md) §2의 export를 같은 셸에서 함께 쓴다(`$ADB` · `$APK` · `$BT`).

- **등록 키는 파일로 남기지 않는다.** 정본은 Secret Manager이고 셸엔 변수로만 둔다(`api-cutover-smoke.md` §5의 토큰 취급과 같은 규율). 위 한 줄이 곧 "서버와 APK가 같은 값을 쓴다"를 구조적으로 보장한다 — 손으로 옮겨 적으면 오타가 403으로만 드러나고, 403은 화면에서 서버 장애와 구별되지 않는다(§6 인지 경로).
- **`$URL`은 `/api/v1`을 포함하지 않는다.** 앱이 붙이고(`$URL/api/v1/auth/device`), dart-define에도 이 형태 그대로 넣는다.

## 2. 코호트 APK — 엔트리 하나 · dart-define 둘

```bash
cd apps/mobile && flutter build apk --release -t lib/main_api_cutover.dart \
  --dart-define=COOKMARK_SERVER_BASE="$URL" \
  --dart-define=COOKMARK_REGISTER_KEY="$REGISTER_KEY"
```

**엔트리는 `lib/main_api_cutover.dart` 하나뿐이다.** 나머지 셋은 코호트에 나갈 수 없다.

- `lib/main.dart` — 프록시 전용. 파일럿 2대의 빌드이고 **flip에서 무접촉**이다(ADR-0004 단일맹검).
- `lib/main_api_spike.dart` — **절대 싣지 않는다.** 부팅에 레시피 3건을 스토리지에 시딩하고 번들 사진으로 인식을 자동 발화한다(실 Gemini 1콜). 레시피 북도 서버에 안 붙는다.
- `lib/main_visual_qa.dart` — 페이크 게이트웨이 전용 QA 하네스다.

### 무엇을 빠뜨리면 무엇이 죽나

이 표가 이 절의 요점이다. **셋 다 빌드가 성공하고 앱이 정상 실행된다** — 실패는 전부 나중에, 조용히 온다([#134](https://github.com/woosung-dev/cookmark/issues/134)가 "핵심 함정"으로 기록한 계열).

| 빠뜨린 것 | 빌드 | 무엇이 죽나 |
| --- | --- | --- |
| `-t lib/main_api_cutover.dart` | 성공 | 기본 엔트리(`lib/main.dart` = 프록시)가 빌드된다. **dart-define 둘이 통째로 무시되고** 코호트가 파일럿 빌드를 받는다. 게다가 `COOKMARK_API_BASE`가 없어 네이티브엔 same-origin이 없으므로 **모든 LLM 호출이 죽는다** |
| `COOKMARK_SERVER_BASE` | 성공 | 컷오버 엔트리가 **조용히 프록시로 폴백**한다 — `lib/main.dart`와 동일 동작이라 화면으로 구별되지 않는다. 레시피 북은 로컬 모드로 굳고(동기 상태가 영구 `ready`) 서버엔 아무것도 안 간다. 여기에도 `COOKMARK_API_BASE`가 없으니 **두 번 조용히 죽는다** |
| `COOKMARK_REGISTER_KEY` (또는 서버 값과 불일치) | 성공 | 부팅은 통과하고 로그인 화면도 없다. 첫 서버 호출에서 등록이 **403**으로 거부되고 인라인 실패 카드가 뜬다. **재시도로 안 고쳐진다** — 빌드에서 빠뜨린 것이면 APK를 다시 뽑는다. 다만 403에는 서버 쪽 원인도 있으니 고치기 전에 함정 첫 항목의 3분기로 가른다 |

**이름을 바꿔 짚어도 조용하다.** `COOKMARK_API_BASE`는 프록시 전용이고 `apps/api` 주소는 `COOKMARK_SERVER_BASE`로만 들어간다([#164](https://github.com/woosung-dev/cookmark/issues/164)). 이름이 갈려 있어 잘못 짚으면 에러가 아니라 **폴백**으로 간다 — 그게 이 분리의 설계 의도이자, 위 표 둘째 줄이 존재하는 이유다.

`android/key.properties`가 없으면 **여기서 즉시 죽는 게 정상이다**(디버그 서명 폴백은 의도적으로 막혀 있다). 그때는 `native-apk-runbook.md` §1로 돌아간다. 산출물 검증(서명·권한·`allowBackup`·라벨)은 같은 문서 §4가 정본이고, 코호트 APK에도 그대로 적용된다.

**`versionCode`는 프록시 빌드와 번호 공간을 공유한다.** 둘 다 `apps/mobile/pubspec.yaml`의 `version: 1.0.0+N` 하나에서 온다. 파일럿 핫픽스가 번호를 올리면 코호트 빌드도 그 번호에서 이어가고, 반대도 같다. 재설치 절차는 어느 쪽이든 `+N`을 올리는 것이다(`native-apk-runbook.md` §6).

## 3. 관통 스모크 — 배포된 Cloud Run + 실 Gemini + 에뮬레이터

**"배포됐다"를 "동작한다"로 착각하지 않기 위한 사람 1회 스모크다.** 자동화하지 않는다 — CI가 Gemini에 도달하지 않는 현재 성질을 유지한다(스펙 #161 Testing Decisions). 왜 이 자리가 비어 있었는지는 §4가 설명한다.

### 3.1 서버 표면 — curl로 먼저 확인한다

```bash
curl -s "$URL/api/v1/health"                                                # → {"status":"ok"}
curl -s -o /dev/null -w '%{http_code}\n' "$URL/api/v1/recipes"              # → 401 (무세션)
curl -s -o /dev/null -w '%{http_code}\n' -X POST "$URL/api/v1/auth/device"  # → 403 (등록 키 없음)

# 등록 — 본문 없는 POST고 등록 키가 유일한 입력이다.
TOKEN="$(curl -s -X POST -H "Authorization: Bearer $REGISTER_KEY" "$URL/api/v1/auth/device" \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["token"])')"
curl -s -H "Authorization: Bearer $TOKEN" "$URL/api/v1/recipes"             # → [] (빈 계정)
```

이어서 **배포된 컨테이너가 실 Gemini에 닿는지**를 텍스트 1콜로 확인한다(원가 ≈ $0.001 미만).

```bash
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"ingredients":["김치","두부","대파"],"recipes":[{"title":"김치찌개","ingredients":["김치","돼지고기","두부","대파"]}]}' \
  "$URL/api/v1/llm/match"
```

`match_score`가 실산출로 나오고 `usage`에 실 토큰 수가 붙으면 **설정 → 팩토리 → SDK → 파싱 경로 전체가 배포된 컨테이너에서 살아 있다**는 뜻이다. 여기까지가 사람이 앱 없이 확인할 수 있는 전부다.

> ⚠️ **이 절이 익명 계정을 1개 남긴다.** 정상이다 — 자동 reaper가 없는 것은 결정이고 파기는 파운더 수동이다(ADR-0012 「backend.md §12 데이터 보호에 대한 명시적 예외」절). 스모크를 여러 번 돌리면 계정이 그만큼 쌓인다.

### 3.2 앱 관통 — 에뮬레이터

§2의 APK를 설치하고(`"$ADB" install -r "$APK"`) **사람이 손으로** 관통시킨다.

1. 첫 실행 — **로그인·회원가입 화면이 없다.** 온보딩에서 바로 코어 루프로 들어간다. 화면 어디에도 `로그인`·`계정`·`세션`·`가입`이 보이지 않는다(등록은 부팅 경로에서 조용히 일어난다).
2. 사진 1장 업로드 → 재료 인식 → **재료 체크리스트**가 뜬다.
3. 레시피 북에 레시피 1건 저장 → 재료가 실추출로 붙는다.
4. 체크리스트에서 재료를 확정 → **제안 최대 3개**까지 간다.

여기까지가 `기기 등록 → 사진 → 인식 → 체크리스트 → 매칭 제안` 관통이다.

### 3.3 서버 레시피 북 CRUD 1바퀴

1. 앱에서 레시피 1건 **추가**.
2. 앱을 완전히 종료하고 **재부팅**.
3. 목록이 그대로 보이고 **레시피 북에 에러 카드가 없다.**
4. 앱에서 그 레시피를 **삭제** → 재부팅 → 사라진 채로 유지된다.

> **3번이 왜 증거인가.** 서버 모드에서 미러는 **서버 응답으로만** 쓰인다 — 저장이 실패하면 미러가 아예 안 바뀌고 실패 카드가 뜬다. 그래서 ①에서 목록에 줄이 생겼다는 것 자체가 서버가 받았다는 뜻이고, ③에서 **재부팅 뒤에도 남아 있다**는 것은 부팅 하이드레이트가 **서버에서 다시 받아왔다**는 뜻이다(하이드레이트는 서버 목록으로 미러를 덮는다). **에러 카드가 없다**가 같은 무게로 중요하다 — 서버에 못 닿으면 목록이 그대로여도 인라인 에러 카드가 뜨고, 그때 화면의 줄은 서버가 아니라 못 덮인 옛 미러다.
>
> **여기서 하이드레이트 가드를 찾지 말 것.** 가드([#165](https://github.com/woosung-dev/cookmark/issues/165))는 "서버 목록이 비었는데 미러는 안 비었다"에서만 발동하는데, 빈 계정으로 시작한 깨끗한 기기에서는 그 조합이 **구조적으로 만들어지지 않는다**(실패한 저장은 미러를 안 건드리므로). 가드가 실제로 발화하는 자리는 **파일럿 데이터를 진 기기가 서버 빌드로 처음 부팅하는 §8 합류**뿐이다.

### 3.4 콜드/웜 지연 기록

**판정 기준이 아니다.** `min-instances`를 0으로 둘지 1로 올릴지(월 $10~15, [#154](https://github.com/woosung-dev/cookmark/issues/154))의 입력이다. 상한선을 지금 박지 않는다 — 측정된 적 없는 숫자에 절반짜리 약을 추정 가격에 선지불하지 않는다.

**콜드** = 15분 이상 유휴 뒤 첫 호출(Cloud Run `--min 0` + Neon Free 유휴 자동 정지). **웜** = 바로 이어서 한 번 더.

| # | 무엇이 겹치나 | 어떻게 재나 | 콜드 | 웜 |
| --- | --- | --- | --- | --- |
| ① | 컨테이너 기동만 | `time curl -s "$URL/api/v1/health"` | | |
| ② | + Neon 웨이크업 + 세션 검증 | `time curl -s -H "Authorization: Bearer $TOKEN" "$URL/api/v1/recipes"` | | |
| ③ | + 실 LLM(텍스트) | §3.1의 `/api/v1/llm/match` curl을 `time`으로 | | |
| ④ | + 실 LLM(사진) + 리사이즈·업로드 | 앱에서 사진 업로드 → 체크리스트까지 초시계 | | |

> ⚠️ **①이 빠르다고 ②·③이 빠른 게 아니다.** health는 DB를 안 만져 Neon을 깨우지 않는다(§4). 네 줄을 따로 재는 이유가 이것이다. 그리고 **②에는 슬라이딩 세션의 대가가 들어 있다** — 인증된 요청마다 `UPDATE` + `COMMIT`이 붙어 왕복이 둘 는다(ADR-0012 슬라이딩 세션 절의 2026-07-29 정정). 임계값 기반 갱신은 이 실측 뒤에 필요가 드러나면 그때 넣는 최적화다.

측정치는 [#170](https://github.com/woosung-dev/cookmark/issues/170)에 첨부한다.

## 4. 이 스모크가 메우는 구멍 — 무엇이 증명되지 않은 채였나

`apps/api`가 배포됐다는 사실과 동작한다는 사실 사이에 **증거가 0건이었다.** 양쪽 끝이 각각 다른 이유로 그 구간을 못 덮는다.

- **배포 스모크의 health는 정적 dict다.** `.github/workflows/api.yml`의 스모크 스텝이 스스로 자인한다 — *"health는 정적 dict라(DB 미접촉) 이건 '리비전이 떠서 트래픽을 받는다'까지만 증명한다. 스키마 증명이 아니다."*
  - **파이프라인이 잡아주는 것도 있다.** 시크릿 넷 중 하나가 **비면** 배포 전 마이그레이션 컨테이너가 `get_settings()`에서 죽고(서버뿐 아니라 `alembic`도 같은 검증을 거친다), `DATABASE_URL`이 **틀리면** `alembic`이 연결에 실패한다. 둘 다 CI가 빨개진다 — 이 둘을 health 탓으로 오해하지 않는다.
  - **잡히지 않는 것이 정확히 하나 남는다 — 값이 있는데 틀린 Gemini 키.** 마이그레이션은 Gemini를 부르지 않고 health는 DB도 Gemini도 안 만진다. 그래서 **배포가 green이고 health가 200인데 인식·추출·매칭이 전부 죽어 있는 상태**가 성립한다. §3.1의 실 LLM 1콜이 정확히 그 구멍을 메운다.
  - Neon이 자고 있어도 health는 200이다(DB를 안 만지니까). 그건 고장이 아니라 설계이고, 대가는 실패가 아니라 **지연**으로 나타난다(§3.4 ②).
- **deep health로 승격하지 않는다.** DB를 만지는 헬스체크로 바꾸면 Cloud Run 헬스체크가 DB를 지속 깨워 **Neon Free의 유휴 자동 정지를 무력화**하고, 그러면 원가 리서치(#154)가 세운 **"월 $0" 전제가 스스로 깨진다.** 그 자리를 메우는 것이 §3이다 — 자동이 아니라 **사람이 1회**.
- **컷오버 E2E는 배선만 증명한다.** `apps/mobile/integration_test/api_cutover_test.dart`가 결정적 페이크 셋(LLM · 서버 레시피 북 · 기기 세션)을 꽂아 돈다. 실 Gemini·실 Neon·실 네트워크에 닿지 않는 것은 **의식적 선택**이다.

### 확인 항목 1건 — 프록시와 같은 Gemini 키인가

`infra/README.md` §3의 시크릿 절차는 `cookmark-gemini-api-key`를 **"기존 Vercel 프록시와 같은 값(루트 `.env.local`)"** 으로 만들라고 적는다. 그대로 했다면 **쿼터가 공유된다.**

실효는 하나다 — 합류 전까지는 파일럿 2대(프록시)와 코호트(`apps/api`)가 같은 무료 티어 쿼터를 태우므로, **코호트 인식 실패의 원인 후보가 하나 늘어난다.** 결정을 흔들지는 않는다(무료 키라 손해 상한이 0이고, 어차피 합류에 프록시 키를 끊는다). 다만 "어제는 됐는데 오늘 안 된다"를 만났을 때 **서버 장애가 아니라 쿼터 소진일 수 있다**는 것을 알고 있어야 한다. 확인은 두 값을 눈으로 대조하는 것으로 족하다.

## 5. 배포 채널 검증 — `versionCode`+1 재설치가 데이터를 보존한다

**roll-forward가 실재함을 코호트 배포 전에 안다.** 이게 없으면 §6의 "클라이언트 결함은 고쳐서 다시 뿌린다"가 종이다. [#133](https://github.com/woosung-dev/cookmark/issues/133)의 핫픽스 리허설을 이 절로 변제한다.

1. §2로 v1을 빌드해 설치한다.
2. **레시피 2~3건을 입력하고 사진 1장을 관통시킨다** — 로컬(이벤트 로그·미러)과 서버(레시피 북) 양쪽에 데이터가 생긴다.
3. `apps/mobile/pubspec.yaml`의 `version: 1.0.0+N`에서 **`+N`을 1 올리고 커밋한다.** 임시로만 덮으려면 `--build-number=N`을 쓴다.
4. §2를 그대로 다시 돌려 v2를 빌드하고 **앱을 지우지 않고 덮어쓴다** — `"$ADB" install -r "$APK"`.
5. 앱을 열어 레시피와 기록이 그대로인지 눈으로 확인한다.
6. 기계적 확인 — `firstInstallTime`이 **그대로**고 `lastUpdateTime`만 바뀌면 OS가 업데이트로 처리했다는 뜻이다.

```bash
"$ADB" shell dumpsys package dev.woosung.cookmark | grep -E "versionCode|firstInstallTime|lastUpdateTime"
```

> ⚠️ **성립 조건은 서명이 같다는 것 하나다.** Android는 서명이 다르면 다른 앱으로 취급해 신규 설치로 처리하고 **데이터를 전멸시킨다**. `android/key.properties`가 파일럿과 같은 키스토어를 가리키는지 확인한다(`native-apk-runbook.md` §1). 서명은 설치 시점까지 보이지 않는 실패 모드다.

> **등록 토큰도 이 경로로 보존된다.** 토큰이 살아야 서버 레시피 북이 계속 그 계정의 것이다. 반대로 **사용자가 앱 데이터를 지우면**(설정 → 저장공간 → 데이터 삭제) 토큰이 사라져 다음 부팅이 새 계정을 받고, 옛 서버 레시피는 도달 불가가 된다 — 그때 남는 복구 수단은 export 파일뿐이다(ADR-0012 「정직한 부정」).

## 6. 되돌림 2단 — 서버 실패는 롤백, 클라이언트 결함은 roll-forward

**되돌림은 런타임이 아니라 배포 채널에 있다.** 런타임 폴백도 원격 킬 스위치도 만들지 않았다([#158](https://github.com/woosung-dev/cookmark/issues/158) 결정 1·3) — 두 백엔드가 등가가 아니라(프록시엔 서버 레시피 북이 없다) 자동 폴백은 강등이 아니라 **조용한 분기**다.

| 실패 | 예 | 되돌림 | 값 |
| --- | --- | --- | --- |
| **서버 실패** | 나쁜 배포 · Gemini 키 만료 · Neon 장애 · 등록 라우트 버그 | **Cloud Run 리비전 롤백** | 분 단위 · 공짜 · 클라이언트 무관 |
| **클라이언트 결함** | base URL 오타 · 등록 키 불일치 · 토큰 저장 깨짐 | **고친 APK 재배포**(roll-forward) | 재빌드 + 카톡 × 5~20명 |
| **전략 후퇴** | 지연·원가가 감당 불가로 판명 | 프록시 APK 재배포 | 같은 값 — 단 서버 레시피 북을 잃는다 |

- **명령은 [`infra/README.md`](../../infra/README.md) §8이 정본이다** — 리비전 목록·트래픽 전환·복구, 그리고 **스키마 변경이 얽히면 롤백이 무효화된다**는 경고까지. 여기서 복제하지 않는다.
- **킬 스위치는 같은 문서 §9다** — 만들 것이 아니라 이미 있는 것이고, 기각된 *앱↔백엔드 전환* 스위치와는 다른 물건이다. 기제와 파급 범위는 그쪽이 정본이다.
- **압도적 다수인 서버 실패는 이미 공짜다.** 우연이 아니라 배포 파이프라인이 그렇게 설계된 결과이고, 근거는 `infra/README.md` §8이 쥔다.
- **프록시 APK는 핫픽스 도구가 아니라 전략 후퇴 전용 산출물이다.** 되돌림 빌드가 코드 0줄인 것은 사실이지만(dart-define 하나 빼고 재빌드하면 그대로 프록시 앱이다) **싸다는 사실이 써야 할 이유는 아니다.** 되돌리면 같은 재배포 값을 치르면서 서버 레시피 북을 잃고 왕복 2회를 문다.

### 허용 다운타임 숫자를 박지 않는다

사이드로드엔 강제 업데이트가 없어 **클라이언트 경로엔 완료 시점 자체가 없다** — 언제 다 고쳐졌다고 말할 수 있는 순간이 정의되지 않는다. 숫자는 지킬 수단이 없는 쪽에 약속만 만든다. 대신 §7이 코호트에게 **기대치를 먼저** 말한다.

### 인지 경로 — 파운더가 사고를 아는 유일한 길

roll-forward는 자동이 아니다. **파운더가 알아야 발동한다.** 그런데 관측·알림 체계는 5~20명 규모에서 **의식적으로 격하**했다(스펙 #161 Out of scope). 그 자리를 메우는 것이 둘뿐이다.

- **실패 문구가 갈려 있다**([#166](https://github.com/woosung-dev/cookmark/issues/166)). 서버 도달 실패·타임아웃에는 "사진 문제가 아니에요"가 먼저 오고 **신고 유도 한 줄이 붙는다** — `계속 이러면 만든 사람에게 카톡으로 알려주세요.` 사용자 입력 실패(인식 결과 없음·어두운 사진)에는 붙지 않는다. 진짜 신고가 소음에 묻히지 않게 하려는 것이다. **문구 정본은 `apps/mobile/lib/ui/widgets/failure_card.dart`이고 여기서 복제하지 않는다.**
- **카톡.** 그게 전부다. 신고가 없으면 파운더가 사고를 모르고, 모르면 **"코호트 2주 무사고"가 무사고와 조용한 이탈을 구분하지 못한다.**

## 7. 코호트 배포 — 기대치를 먼저 말하고 뿌린다

**하나의 APK를 5~20명이 받고 각자 자기 계정을 갖는다.** 등록이 기기마다 새 익명 계정을 내므로 사람마다 빌드를 뽑지 않는다(1빌드 = N계정).

**코호트는 빈 계정 시작 · 이전 없음이다.** bulk 이전은 §8에서 파일럿 2대에만 쓴다 — flip과 이전의 실패 표면을 겹치지 않게 하려는 것이다.

설치 손가락 순서는 `native-apk-runbook.md` §5와 같다(사이드로드 경고 · Play Protect). 단 **코호트는 파운더가 대신 깔아주지 못하므로 그 화면들을 미리 말해준다** — 단일맹검(ADR-0004)은 파일럿 2대에만 걸린 제약이고 코호트엔 없다.

### 기대치 고지 문안

APK보다 **먼저** 보낸다. 그대로 복사해 쓴다.

> 냉파라는 앱을 만들어봤어요. 냉장고 사진 한 장 찍으면 뭘 해먹을지 골라주는 앱이에요.
>
> 먼저 말씀드릴 게 세 가지 있어요.
>
> - **취미로 만든 거라 가끔 안 될 수 있어요.** 회사가 만든 게 아니라 저 혼자 만든 거예요.
> - **안 되면 저한테 카톡으로 알려주세요.** 앱에 "지금 연결에 문제가 있어요"라고 뜨면 제 쪽 문제예요 — 사진 탓이 아니니 다시 찍지 않으셔도 돼요. 알려주셔야 제가 압니다.
> - **고치는 데 며칠 걸릴 수 있어요.** 바로 못 고쳐도 손 놓은 게 아니니 조금만 기다려주세요.
>
> 설치할 때 "알 수 없는 앱"이라고 경고가 뜰 텐데 정상이에요. 스토어에 올린 게 아니라서 그래요.
>
> 써보고 재미없으면 그냥 지우셔도 돼요. 부담 갖지 마세요.

"며칠"은 **상한 약속이 아니라 기대치다** — 위 §6대로 지킬 수단이 없는 숫자를 약속하지 않는다.

> **앱 안의 「인식이 틀려도 괜찮아요」 문구와 헷갈리지 말 것.** 그건 첫 인식 결과 위에 1회 뜨는 *오인식* 기대치 문구이고, 여기 문안은 *장애·수리 시간*에 대한 기기 밖 고지다. 서로 대체하지 않는다.

### 파운더가 알고 있어야 할 것 (문안에는 넣지 않는다)

- **앱 데이터를 지우면 새 계정을 받는다.** 서버 레시피는 도달 불가가 되고 로컬 미러도 함께 사라진다. 복구 수단은 export 파일뿐이다. 앱 안에 이 토큰을 초기화하는 장치는 없다 — 지우는 경로는 앱 삭제와 데이터 삭제뿐이다.
- **앱 삭제로는 서버 데이터가 지워지지 않는다.** 도달 불가 계정은 잔존하고 파기는 파운더가 일괄 삭제로 한다(ADR-0012 「backend.md §12 데이터 보호에 대한 명시적 예외」절 · 트리거 = 승격 시 또는 코호트 종료 시).
- **코호트 이벤트는 수집하지 않는다.** 서버에 받을 곳이 0건인 **결정**이지 결함이 아니다. 이벤트 로그는 기기 로컬에 남아 "자주 쓰는 재료" 칩을 먹인다.

### ━━━ 여기가 되돌릴 수 없는 선이다 ━━━

APK가 코호트에게 나가는 순간. 그 **앞**은 전부 서비스 삭제·재배포로 공짜로 뒤집히고, 그 **뒤**는 남의 손에 들어간 APK라 원격으로 못 되돌린다(사이드로드엔 강제 업데이트가 없다). 앞 절들이 전부 이 선 위에 놓인 이유다.

## 8. 합류 — 파일럿 2대 이전 5단계

**발동 조건 = 8/5 파일럿 판정 완료 + 코호트 2주 무사고**(파운더 직접 확인). **8/5가 되자마자 합류하면 카나리아를 세운 의미가 없다.**

평생 1회, 2대 한정이다.

1. **프록시 빌드에서 export** — 레시피 북 하단 「기록 복사하기」. ← 실패 시 **지난 일요일 백업 파일이 대체 vehicle**이다(주간 백업 파일이 곧 이 파일이라 파운더 폴더에 이미 있다).
2. **서버 빌드 APK 설치** — §2의 APK. 같은 키스토어 · `versionCode`+1 (§5가 이미 검증한 경로).
3. **부팅 → 기기 등록 → 하이드레이트** — 새 익명 계정은 비어 있고, **하이드레이트 가드가 빈 서버 목록으로 미러를 덮지 않는다**(#165). 화면상 레시피 북은 그대로다.
4. **가져오기 → bulk 이전** — 재료 그대로 · LLM 호출 0회 · 원자적(전량 성공 또는 전량 실패).
5. **성공 후 재수화** — 서버가 부여한 id가 붙은 목록이 미러로 되돌아온다. 다음 부팅엔 가드가 지킬 것이 없다.

> ⚠️ **가져오기(④)를 어떤 저장보다 먼저 한다.** 서버 북이 한 건이라도 차면 하이드레이트 가드가 무효가 되어(가드는 서버 목록이 **빈** 경우에만 발동한다) 나머지 미이전 레시피가 **다음 부팅에 조용히 사라진다.** 실패 시 대체 vehicle은 지난 일요일 백업 파일이다.

### ④의 손가락 순서

레시피 북 하단 「백업」 섹션에서.

1. 「가져오기」 입력란에 ①에서 복사한 JSON을 **붙여넣는다.**
2. **「무엇이 들어올지 보기」** — 미리보기가 뜬다.
3. 미리보기가 `새로 들어올 레시피가 없어요 — 이미 다 있어요.`라고 말해도 **정상이다.** 미러 기준 dedup이라 자기 export 파일은 전부 "이미 있음"으로 잡힌다. 그 아래 **`아직 서버에 없는 레시피 N개도 함께 올립니다.`** 한 줄이 이 절차의 핵심이고, N이 이전 대상 수다.
4. **「가져오기」** — 확정. N이 0이 아니면 버튼이 열려 있다.
5. 목록을 새로 못 불러왔다는 안내가 뜨면 업로드는 **성공한 것이다** — 앱을 새로고침하면 반영된다.

레시피 북이 아직 서버와 연결되기 전이면 미리보기·확정이 거부된다(`서버의 레시피 목록과 연결된 뒤 가져올 수 있어요.`). 잠시 뒤 다시 한다.

### 합류 발동 확인

**파일럿 2대 모두 새 APK로 교체됐음을 파운더가 직접 확인한다.** 2대뿐이라 이 확인이 성립한다.

이 확인이 [#171](https://github.com/woosung-dev/cookmark/issues/171)(엔트리 통합 + Vercel 프록시 4표면 은퇴)의 **하한**이다 — 파일럿 2대의 구 APK가 프록시 함수의 유일한 정당한 소비자이고, 사이드로드엔 강제 업데이트가 없어 그 2대가 교체되기 전엔 끊을 수 없다. 합류가 그 밖에 무엇을 함께 하는지는 #171이 정본이다.

## 함정

- **`지금 연결에 문제가 있어요.`가 계속 뜬다** — 등록 거부(403)일 수도, 서버가 죽은 것일 수도 있다. **화면 문구로는 구별되지 않는다**(그게 이 문구의 설계다 — 사용자에게는 어느 쪽이든 "네 탓이 아니다"가 참이다) → §1의 `$REGISTER_KEY`로 §3.1의 등록 curl을 직접 돌려 셋으로 가른다.
  - **연결 실패·5xx** → 서버 쪽이다. `infra/README.md` §8 리비전 롤백.
  - **200** → 서버도 살아 있고 지금 Secret Manager 값으로 등록도 된다. 그러면 **APK에 박힌 값이 지금 서버 값과 다르다**(회전했거나 오타) → **새 APK**.
  - **403** → 지금 Secret Manager 값을 서버가 거부한다. 즉 **컨테이너가 읽은 값이 그보다 옛 버전**이다 — 키를 회전하고 **새 리비전을 배포하지 않은** 상태가 대표적이다 → 새 리비전 배포(아래 회전 3종 세트). 이 경우 새 APK를 뽑아도 안 고쳐진다.
- **레시피 북이 로컬 모드로 보인다** — 저장은 되는데 서버에 안 가고 동기 상태가 늘 정상이다 → `COOKMARK_SERVER_BASE`를 빠뜨렸다(§2 표 둘째 줄). 빌드가 성공했으므로 눈치채기 어렵다. §2 명령을 통째로 복사해 다시 뽑는다.
- **`접속 정보가 유효하지 않아요.`가 뜬다** — 재등록까지 실패한 **진짜 401**이다. 등록 키 오류가 **아니다** — 그건 다른 값으로 접혀 이 문구가 안 나온다. 서버 쪽을 본다.
- **첫 요청만 7~15초 걸린다** — 콜드다(Cloud Run `--min 0` + Neon 유휴 정지 + LLM). 실패가 아니다 → §3.4에 기록하고 `min-instances` 결정의 입력으로 쓴다.
- **health는 200인데 앱이 안 된다** — health가 DB를 안 만진다(§4). `DATABASE_URL`·Gemini 키·등록 키 중 무엇이 틀려도 health는 200이다 → §3.1을 순서대로 돌려 어디서 끊기는지 본다.
- **파운더 기기에 파일럿 빌드가 깔려 있다** — 애플리케이션 ID와 키스토어가 같아 코호트 APK가 **업데이트로 덮인다.** 파일럿 데이터 위에서 서버 모드가 뜨는 상태다(가드가 미러는 지키지만 측정이 오염된다) → **스모크는 에뮬레이터나 클린 프로필에서 한다.**
- **하이드레이트 가드가 발동했는지 알고 싶다**(§8 합류에서만 발화한다) — UI 안내는 의도적으로 없다 → 백업 내보내기(레시피 북 하단 「기록 복사하기」)로 export JSON을 뽑아 `"type":"errorShown"` + `"kind":"emptyServerBook"` + `"stage":"hydrate"`를 찾는다. 있으면 그 기기는 **"아직 이전 안 됨"** 상태이고, §8 ④를 아직 안 한 것이다.
- **등록 키를 회전했더니 코호트가 통째로 등록 불가다** — 회전은 셋이 한 묶음이다: `gcloud secrets versions add` → **새 리비전 배포**(시크릿 env는 기동 시 1회 해석된다) → **새 키를 박은 APK 재배포**. 셋 중 하나라도 빠지면 옛 키가 계속 먹거나 신규 등록이 전부 막힌다. **기존 세션은 불변**이라 이미 등록한 기기는 계속 돈다.
- **스모크가 익명 계정을 여러 개 남겼다** — 정상이다. 자동 reaper는 만들지 않기로 했고 파기는 파운더 수동이다(ADR-0012). 5~20명 규모에서 수십 행이라 실해가 0이다.
- **APK를 뽑았는데 부팅에 레시피 3건이 이미 있고 사진이 저절로 돈다** — `main_api_spike.dart`를 빌드했다 → `-t lib/main_api_cutover.dart`를 확인한다. 이 엔트리는 코호트에 나가면 안 된다.
